# ADR 0011 — App-authored spacing is a tokenized six-step scale; `libs/ui` is not

- Status: accepted
- Date: 2026-09-06
- Scope: frontend/src/app, frontend/src/styles.css, tools/lint/rules/no-literal-spacing.mjs, stylelint.config.mjs. Explicitly not in scope: frontend/libs/ui.

## Context

An audit of `docs/architecture/design.md` against the running codebase found seven of its eleven "non-negotiable feel" claims false, self-contradictory, or true only by an inheritance the document never named. Two of those seven are spacing claims, and they contradict each other in the same paragraph: the doc says "4px base" and in the next sentence tells you to use `px-2.5`, which is 10px. Neither half was invented for this ADR — grepping the app before this branch found nine distinct spacing magnitudes in `frontend/src/app`, used with no shared rationale. Nine numbers nobody agreed on together is not a design language, it is nine separate decisions that happened to compile.

Tailwind 4 makes the failure mode structural, not accidental. `gap-2`, `p-3`, `mt-5` all resolve to real CSS the moment Tailwind's default spacing scale is in scope, which it is by default. Declaring a token does nothing to that resolution — Tailwind does not know or care that a token exists elsewhere; the numeric utility keeps working right alongside it. A scale that is only a set of CSS variables and a convention to use them is decoration. The first person who reaches for `gap-2` instead of `gap-m` gets a working build and a silent drift back to the thing the scale was supposed to prevent.

`frontend/libs/ui` is the confound that makes a single scale for "the frontend" the wrong design. It is spartan's nova style, generated by `ng g @spartan-ng/cli:ui` and reasserted byte-for-byte by `npm run ui:style` (ADR 0010). It carries its own spacing rhythm — half-steps between Tailwind's integer stops, like `px-2.5` and `gap-1.5` — inlined into the generated `.ts` files at generation time. ADR 0010 already drew the line between what is authored and what is generated for the *component* question; this ADR draws the same line for *spacing* specifically, because the previous investigation counted 77 half-step spacing utilities in `libs/ui` alone, and no version of an app-authored scale absorbs 77 vendored decisions without becoming a description of spartan's nova style rather than jig's.

## Decision

- **Supersedes the spacing half of ADR 0010, and only that half.** ADR 0010 decided that `libs/ui` is generated output YAGNI does not govern, and that its literal `h-8` / `px-2.5` control-size-and-spacing utilities are baked at generation time, not token-driven. Both of those facts stand unchanged — they are the mechanism that makes the split in this ADR necessary, not a problem this ADR fixes. What ADR 0010 did not yet have was an app-side scale to be inconsistent with `libs/ui`'s spacing. This ADR supplies that scale and states the boundary explicitly, because ADR 0010 left the app-authored side of spacing undecided rather than wrong.

- **App-authored spacing is six steps on a 4px grid**, declared once in `frontend/src/styles.css` as Tailwind `@theme` entries so each step becomes real utilities (`gap-m`, `px-l`, `mt-xs`) alongside — not instead of — Tailwind's numeric ones:

  | Step | rem | px |
  |---|---|---|
  | `xs` | 0.25rem | 4px |
  | `s` | 0.5rem | 8px |
  | `m` | 0.75rem | 12px |
  | `l` | 1rem | 16px |
  | `xl` | 1.5rem | 24px |
  | `2xl` | 2rem | 32px |

  These six values are not invented. They are the nine magnitudes the app already used, collapsed onto the nearest 4px grid line and de-duplicated. The scale describes what the app already needed, on a grid it did not previously enforce.

- **`libs/ui` keeps spartan's half-steps, permanently, not as a migration debt.** The vendored kit inlines 77 half-step spacing utilities today — `px-2.5` (x18), `gap-1.5` (x14), `px-1.5` (x11), `py-1.5` (x8), `gap-0.5` (x8), `gap-2.5` (x5), `py-0.5` (x4), `py-2.5` (x3), `p-2.5` (x3), plus single uses of `pr-2.5`, `pb-2.5`, and `mx-3.5`. Every `npm run ui:style` regenerates them from spartan's `style-nova.css` and reasserts the same rhythm. A primitive's internal padding therefore sits up to 2px off the app's 4px grid, and that is accepted rather than patched: patching it means hand-editing generated files, which ADR 0010 already forbids for the same reason it forbids everything else hand-edited in `libs/ui` — the edit survives until the next regeneration and then silently disappears.

  **An eight-step scale that absorbed spartan's half-steps was considered and rejected.** It would have made the app-authored scale and the vendored scale the same set of numbers, which sounds like unification. It is the opposite: it makes jig's design language a function of spartan's current nova build, so the day `ui:style` regenerates against a different spartan release with a different inlined rhythm, jig's own token scale would need to change to match a vendor's internal choice it does not control and cannot pin. A jig token answers to `styles.css`; it must never answer to what `npm run ui:style` happened to inline last. Six steps that describe the app, sitting beside 77 half-steps that describe a vendored dependency, is the honest shape. It is two rulers, not one ruler that bends.

- **Two engines enforce the app-authored scale, because a token alone enforces nothing.** `frontend/stylelint.config.mjs` runs `scale-unlimited/declaration-strict-value` against `padding`, `margin`, `gap`, `background`, `border-radius` and colour properties in authored CSS, forbidding a literal where a `var(--token)` belongs. `tools/lint/rules/no-literal-spacing.mjs` covers the half Stylelint cannot reach — Tailwind spacing utilities written directly in Angular templates — by rejecting a numeric or arbitrary value on any `gap`/`padding`/`margin` family utility, `sm:gap-2` and `dark:hover:p-4` included, with `0`, `auto`, and `gap-px` (the 1px hairline primitive) exempted. Neither engine touches `frontend/libs/ui`: Stylelint has nothing to scan there — the generated kit ships zero `.css` files and zero inline styles — and `no-literal-spacing` excludes it by design, the same way YAGNI excludes it under ADR 0010. Enforcing a vendored file that the next `ui:style` run overwrites regardless would be theatre.

- **Consequence: 29 sites moved by up to 2px.** Every app-authored spacing literal that this branch replaced snapped to its nearest step on the 4px grid rather than staying at its exact prior value. This is recorded as a deliberate visual change, not a pure refactor — a handful of call sites read a hair tighter or looser than before, and that was accepted in exchange for nine ad-hoc magnitudes becoming six agreed ones.

## Consequences

- The app has one spacing vocabulary, gated at commit time by two tools instead of governed by a doc comment nobody re-reads. Reaching for a raw Tailwind number in `frontend/src/app` now fails the build; reaching for one in `frontend/libs/ui` is not just permitted, it is the only supported state, because that tree is never hand-edited (ADR 0010).
- `docs/architecture/design.md` is rewritten alongside this ADR to state the app-authored rules and the vendored-kit facts as two lists in two voices, rather than one list that quietly averages a governed codebase and an ungoverned one.
- The split is a standing cost, not a one-time one: every future spartan style change can shift `libs/ui`'s spacing rhythm further from the app's 4px grid, and this ADR is the record that the resulting mismatch is intended, not a defect to be fixed by absorbing spartan's numbers into the token scale.
- A future rewrite of the app's own scale (adding a step, changing a value) is a normal token-and-gate change under this ADR. A future spartan style change altering `libs/ui`'s half-steps requires no change here at all — it is exactly the variance this ADR already accounted for.
