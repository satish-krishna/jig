## Button — `button`

![Button](images/button.png)

- **Variants** — Six semantic variants; the same classes apply whether the host is a button or an anchor.
- **Sizes** — Text sizes pair with a matching square icon size for icon-only buttons.
- **States** — Disabled is a static attribute; the loading state is a real signal flipped by the click handler.
- **With icons** — The data-icon attribute, inline-start or inline-end, tells the button's own padding utilities which side the icon sits on.

<a id="button-group"></a>
## Button group — `button-group`

![Button group](images/button-group.png)

- **Orientation** — Horizontal is the default; vertical stacks the same buttons top to bottom.
- **Sizes** — Match every button in a group to the same size.
- **States** — Locking is real signal state — the Lock button disables every action in the group below it.
- **Composed with text and an input** — hlmButtonGroupText and a plain hlmInput slot into the same row as a button.

<a id="toggle"></a>
## Toggle — `toggle`

![Toggle](images/toggle.png)

- **Variants** — default stays transparent until pressed; outline adds a resting border.
- **Sizes** — sm, default and lg, all outline.
- **Pressed and disabled** — Bookmark is driven by a real two-way [(state)] binding, not a hand-set aria-pressed.
- **In a field** — Paired with hlmField the same way a checkbox is — the label's for points at the toggle's id.

<a id="toggle-group"></a>
## Toggle group — `toggle-group`

![Toggle group](images/toggle-group.png)

- **Single vs. multiple** — type=single is exclusive; type=multiple lets several items stay pressed. Both bound with [(value)].
- **Sizes** — sm and default, both outline, single selection.
- **Disabled** — disabled on the group reaches every item.
- **In a field** — The description text is read straight off the group's own value signal — no duplicated state.

- **Loading toggle** — Driven by a real signal — the skeleton is swapped for actual content, never forced.

## Sonner — `sonner`

![Sonner](images/sonner.png)

- **Types** — success / error / warning / info, plus dismissing every visible toast.
- **Description and action** — A second line plus a clickable action button on the toast itself.
- **Positions** — Per-toast position overrides the toaster default.

<a id="schema-form"></a>
## Schema form — `schema-form`

![Schema form](images/schema-form.png)

- **Render a schema** — The schema is the only input; the output is already parsed and valid.
- **Every control kind** — Inference with no control override. Every registered leaf control kind on a four-column layout.
- **Nested objects and arrays** — A group control nesting an address form, and an array-of-objects repeater for contact entries.
- **Validation folds back onto the fields** — Press Send with the form empty — each zod message lands under the field that raised it.
- **The schema is an input** — Swap it and the whole form is rebuilt. This is what separates the renderer from a hand-written form.

<a id="signal-form"></a>
## Signal form — `signal-form`

![Signal form](images/signal-form.png)

- **An authored form** — The model type is z.infer — never a hand-written interface. Reference: features/users/user-form.ts.
- **Labels come from the schema** — formMeta(schema) reads .meta() off each field. No label string is written in the template.
- **Validation is native zod** — Pre-filled with a bad address and touched, so the schema's own message is on screen.
- **Submit runs only when valid** — submit() never invokes its callback on an invalid form, so there is no guard to forget.
