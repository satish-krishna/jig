# DR0002 — Architecture ruleset is empty

> Engine: `tools/analyzers/Jig.Analyzers/LayerDependencyAnalyzer.cs`. Ruleset: `tools/analyzers/Jig.Analyzers/ArchLayers.txt`. Decision: [ADR 0009](../../../.bob/adr/0009-architecture-rules-are-compiler-errors.md).

## What it forbids

A compilation in which `ArchLayers.txt` parsed to zero rules — the file is missing, empty, or contains only comments. The diagnostic is reported at `CompilationEnd`, so it fires once per compilation rather than per file.

## Why

Absence of complaint is not innocence. If the ruleset vanishes, DR0001 has nothing to enforce and every build goes green while the layer rules are gone. A check that reports success because it found nothing to check is paperwork.

This closes the deletion door from inside the compiler, which is the only place it can be closed completely. The `PreToolUse` guard watches `Bash` as well as `Write` and `Edit`, so it now denies a literal `rm ArchLayers.txt` — but that is a heuristic over a Turing-complete shell, and a path assembled from variables or a deletion through a language runtime still gets through. The analyzer does not watch for the act; it asks the compilation what it actually holds, so it fires whatever removed the file and by whatever means.

## Restore it from git

    git checkout -- tools/analyzers/Jig.Analyzers/ArchLayers.txt

If the file was emptied deliberately, that is a law change and belongs in a reviewed diff with the reasoning attached, not in a build that quietly passes. If you are removing the last rule because the rules are wrong, remove the analyzer wiring too and say so in an ADR — a live analyzer with an empty map is the one state this diagnostic exists to forbid.

## Known blind spots

**It guards the ruleset's existence, not its integrity.** A file that still parses to one or more rules keeps DR0002 quiet even if a rule was lost to a typo. [DR0003](DR0003.md) covers that case.

**It cannot fire from a compilation it never joined.** Deleting `services/api/src/Directory.Build.props` or the `tools/analyzers/` tree unloads the analyzer entirely, and neither DR0002 nor DR0003 can report from outside the build. That door is not closeable from inside the repo, and the design does not pretend otherwise: what catches it is the diff, read by someone who treats an enforcement change as a law change, and CI running the same rules from a clean checkout where the agent's hooks do not exist.

Every guard here has an off switch here. All we choose is how loud the switch is.
